## Problem Statement
Mine haul roads get fixed reactively, when a truck gets stuck, breaks down or someone complains. There is no number that shows a road section getting worse before it fails. TM 5-626 (US Army, 1995) defines the Unsurfaced Road Condition Index (URCI), but doing it by hand is slow. You measure 7 distress types at L/M/H severity, compute densities, read deduct values off Appendix C curves, sum them (TDV), count the deduct values greater than 5.0 (q, per §3-4b(3)), and read URCI off Figure C-8. Nobody at the site does it today.

URCI Field is an Android app that lets an inspector enter raw measurements and immediately get the URCI. Each entry can have photo evidence stamped with the distress type, severity, time and location. The app prints a DA Form 7348-R style sheet and keeps a per-section history the mine engineer can graph and export, all fully offline.

## Target User & Narrowest Wedge
- **Primary user:** the mine engineer or planner, who needs a per-section URCI trend to justify grading, drainage and aggregate work before production suffers. No individual is named yet (see The Assignment).
- **Secondary user:** the field inspector who enters data, often more comfortable in Indonesian than English.
- **Wedge:** one inspection gives a live URCI, stamped photos and a DA 7348-R PDF. Repeated inspections give a section trend graph.

- **Data on phone storage** in a user-visible folder that can be copied to a PC. Because of Android 11+ scoped storage, re-reading after a reinstall requires the user to re-select that folder (see Storage access).

- **Metric units.**
- **Maintainable by the owner,** who already writes single-file HTML/JS (GeoMap Field).

## Premises
1. The primary user is the mine engineer or planner. The core payoff is the per-section URCI trend; field entry must be fast.
2. **Curve math.** The Appendix C deduct curves and the Fig C-8 TDV-q curves are digitized as point tables with linear interpolation. See URCI calculation rules for exact handling.
   - The math is accepted only if both PDF worked examples reproduce within ±2 URCI from their **metric** inputs.
     - FS 144: 130 m², with 81-M 30.5 m, 82-H 61.0 m, 84-L, 86-M 45.5 m² and 86-H 84.5 m². That gives densities 23.5/46.9/35.0/65.0, deducts 19/36/2/31/44, TDV 132, q 4, URCI 25.
     - FS 101: 167.4 m², with 81-L 30.5 m, 83-M 83.7 m², 84-M and 87-M 48.8 m. That gives densities 18.2/50.0/29.2, deducts 13/29/4/18, TDV 64, q 3, URCI 59.
   - Each curve also gets 2–3 hand-read checkpoints, because the examples never exercise 85, or 87 at high severity.
3. **Metric units** (m, m², count). TM 5-626 provides separate metric curves for 81 (Fig C-1), 82 (C-2), 85 (C-5) and 87 (C-7). The app digitizes and uses those metric curves, with density = quantity / sample area (m²) × 100. Curves 83 (C-3) and 86 (C-6) are area ratios valid for either unit system. Distress 84 (Dust) uses fixed deducts of L=2, M=4, H=15 with no density. No unit conversion is applied anywhere.
4. **Storage.** Offline-first, with all data on the device. The export bundle is the handoff format, and import merges by record UUID using the sync rules below.
5. **Exports:**
   - per-inspection DA 7348-R style PDF plus a photo appendix page;
   - all data as .xlsx;
   - graphs as PNG/PDF.

   All are generated on the device.
6. **Section score.** Section URCI is the mean of its sample units. A unit more than 10 points below the mean is flagged (TM 5-626 §4-2b).
7. **(Revised by owner)** The app is an Android APK. Data and photos are stored on phone storage in a user-visible data folder, `<data folder>`, chosen on first run with `Documents/URCI` suggested. There is one subfolder per inspection.
   - **Photos** are resized to 2048 px on the long side and saved as JPEG at 85% quality, about 400–600 KB each.
   - **Built** by GitHub Actions and published as GitHub Releases.
8. **(Added by owner)** Photo evidence per distress entry.
   - **Stamp:** a permanent stamp drawn onto the image before compression, showing distress code and name, severity, date/time, branch/section/unit, and GPS ± accuracy when available. Example: `83 KERITING · M · 01/10/26 10:11`.
   - **Gallery imports** follow the Photo rules below. They are always marked as imported, never presented as live captures.
9. **(Added by owner)** Settings:
   - **Rating bands:** 5 editable bands, defaulting to Sangat Baik 85–100, Baik 65–84, Sedang 45–64, Buruk 25–44, Sangat Buruk 0–24. The app stores the raw URCI and derives the rating at display time (rounding and validation in URCI calculation rules). Every export prints the band table it used.
   - **Language:** an ID/EN switch covering all labels, distress names, photo stamps and PDFs.
   - **Source footnote:** "Department of the Army, TM 5-626, *Unsurfaced Road Maintenance Management*, 16 January 1995", shown at the bottom of Settings and in every PDF footer.

## Approaches Considered
### Approach A: Web app wrapped as an APK with Capacitor (CHOSEN)
HTML/JS UI packaged as a native Android app. Capacitor plugins handle the camera, GPS (satellite, works offline) and filesystem. Effort M (human ~2 weeks / CC ~2–3 h), low risk. Reuses the owner's HTML/JS skills and GeoMap Field's patterns, and the same code runs in a desktop browser for testing.
### Approach B: Native Kotlin (Compose + Room + CameraX)
Rejected for now: the longest build (human ~5–6 weeks), and the owner can't easily maintain it.
### Approach C: Excel template plus a timestamp-camera app
Rejected: photos wouldn't be linked to entries, and phone entry would be clumsy. Kept only as a fallback demand test.

## Recommended Approach
Approach A, with fully offline as a hard requirement.

**Architecture**
- **Project:** a new folder `urci-app/` in the repo (Capacitor project). The web code lives in `urci-app/www/`, plain HTML/CSS/JS with no runtime network calls.
- **Bundled libraries,** all vendored, never CDN at runtime (no JS zip library is needed, because zipping runs natively):
  - Chart.js for graphs;
  - SheetJS (xlsx) for Excel export and import;
  - jsPDF for the DA 7348-R and photo-page PDFs.
- **Capacitor plugins:**
  - `@capacitor/camera` for photo capture;
  - `@capacitor/geolocation` for GPS;
  - `@capacitor/filesystem`, **app-private only:** `Directory.Data/pending/` for raw photos waiting to be stamped, `Directory.Cache` for import staging, and `Directory.Data` for `device.json` (deviceId and edit counter). It never touches the shared data folder.
  - `@capacitor/share` to send files when a connection exists.
  - **`UrciStorage`, a small custom Capacitor plugin** in Kotlin (about 300 lines, in the repo under `urci-app/android/`). It provides:
    - folder access through Android's Storage Access Framework (SAF) and the DocumentFile API: list, read text, write text, write a JPEG from a temp file, and create-new without overwrite;
    - `pickFolder` (ACTION_OPEN_DOCUMENT_TREE with a persisted URI permission);
    - `pickFile` (ACTION_OPEN_DOCUMENT for `.urci.zip`);
    - streaming `exportZip(paths[] → target)` and `importZip(source → staging folder)` using `java.util.zip`, so photos never pass through the WebView as base64.
  - **An incoming intent filter** so a `.urci.zip` received through WhatsApp, Bluetooth or a file manager offers "Open with URCI Field". It goes into the same import flow.
- **Modules:**
  - `urci-engine.js`: pure functions with no DOM. It covers curve tables, interpolation with clamp and flag, density, deducts, TDV, q, URCI, section average and outlier flag. Runs with Node for tests.
  - `curves.json`: digitized point tables for 81–87 × L/M/H plus the TDV-q curves for q = 1…7. Includes the source figure for each table.
  - `i18n.js`: ID/EN strings, including distress names.
  - `store.js`: all persistent reads and writes of `<data folder>`, exclusively through `UrciStorage`.
  - `stamp.js`: canvas burn-in, then resize, then JPEG at 85% quality.
  - `export.js`: builds the PDF, xlsx and export bundle.
- **Storage access:**
  - **First run:** the app asks the user to choose or create a folder, suggesting `Documents/URCI`. It keeps a persisted SAF permission. Everything below lives inside that folder.
  - **After a reinstall** (or a new phone with the folder copied over), the first run asks for the folder again. The app detects an existing `settings.json` and re-reads all inspections. This is the supported "survives uninstall" path. It needs no broad storage permission and is tested on Android 11, 13 and 14.
- **Data layout in the chosen folder:**
  - `inspections/20261001_I-HR01_S03_SU2_a1b2c3d4/inspection.json` plus photos.
    - The folder name is `{yyyyMMdd}_{branch}_{section}_SU{n}_{first 8 of the record UUID}`. It is fixed at creation and never renamed when header fields are edited later. The UUID inside `inspection.json` is the only key.
    - Folder-name tokens are sanitized: `{branch}` and `{section}` in the folder name are the header values with every character outside `[A-Za-z0-9-]` replaced by `-`, truncated to 20 characters, or `X` if empty. The original header text is kept unchanged inside `inspection.json` for display and exports.
    - Photo names are `{code}-{sev}-{yyyyMMdd-HHmmss}-{first 8 of the photo UUID}.jpg`, for example `83-M-20261001-101107-9f3e2c11.jpg`. Writes use create-new and never overwrite an existing file.
  - `<data folder>/exports/` for PDFs, xlsx files and `.urci.zip` bundles;
  - `<data folder>/settings.json` for bands, language and section list. `deviceId` is never stored here; it lives in app-private `device.json`, and a reinstall always generates a new one. The Android manifest sets `android:allowBackup="false"` and `dataExtractionRules` that exclude all app-private files, so Auto Backup and device-to-device transfer never restore `device.json`. A reinstall or a new phone always gets a fresh deviceId.
- **Export bundle:** a `.urci.zip` holding `manifest.json` (`{"format":"urci-bundle","version":1,"createdBy":deviceId,"count":N}`) plus `inspection.json` files (including tombstones) and their photos, written by the native `exportZip`.
  - **Scopes:**
    1. **Full backup:** everything. It resets the "last backup" counter.
    2. **Share selection:** chosen inspections or a section and date range.
  - **Memory:** there's no in-memory size cap, because zipping streams natively. A Full backup is split into parts of at most 1.5 GB uncompressed (`backup-<yyyyMMdd>-part1of3.urci.zip`, …). Each part is a complete, independently importable bundle with its own `manifest.json`, so every part stays under the 2 GB import limit. If a bundle is over 100 MB, the share sheet warns that messaging apps may reject it.
  - **Import** treats every bundle as untrusted:
    1. `importZip` unzips natively into an app-private staging folder (`Directory.Cache/import-<uuid>/`), never directly into `<data folder>`.
    2. It rejects the whole bundle if any entry has an absolute path or a `..` segment, or isn't one of:
       - `manifest.json`;
       - `inspections/<folder>/inspection.json`, where `<folder>` matches `^\d{8}_[A-Za-z0-9-]{1,20}_[A-Za-z0-9-]{1,20}_SU\d{1,4}_[0-9a-f]{8}$`;
       - `inspections/<folder>/<name>.jpg`;
       - `rounds/<roundId>.json`, where `<roundId>` is a UUID.
    3. Limits: at most 20 MB per entry, 2 GB total uncompressed, and 20,000 entries.
    4. A missing or wrong `manifest.json` gives the message "Bukan file bundel URCI / Not a URCI bundle".
    5. Each `inspection.json` is schema-validated (required fields, types, UUID format, distress codes 81–87, severities L/M/H) before any merge.
    6. Accepted records are applied through `UrciStorage` create-new writes plus the sync rules. Staging is deleted afterwards.
  - **Opening a bundle:** Android can't match the double extension `.urci.zip` on content URIs, so both the intent filter ("Open with URCI Field") and `pickFile` use MIME types `application/zip` and `application/octet-stream`. The `manifest.json` check is what identifies a real bundle.
- **Sync rules (merge by UUID, no reliance on clocks):**
  - **Edit history:** every record carries `history`, a list of `{deviceId, n}` edit stamps. `deviceId` is a random ID per install; `n` is that device's edit counter. Each save appends a stamp.
  - **Applying an imported record:**
    - incoming history contains local's latest stamp: take the incoming record (fast-forward);
    - local history contains incoming's latest stamp: keep local;
    - neither: **conflict**. Nothing is overwritten silently.
  - **While a conflict is open:**
    - The incoming version is stored as `inspection.conflict-<deviceId>-<n>.json` in the same inspection folder. Its photos keep their unique names; a name already present is skipped as an identical file.
    - The record shows "⚠ Konflik" in History, and the user picks one version side-by-side.
    - Until it's resolved, the trend point, section mean, PDF/xlsx exports and outgoing bundles use the **local** version, and exports mark it "⚠ konflik belum diselesaikan". Outgoing bundles never include the `.conflict-*` file.
  - **Resolving** writes a new version: the chosen content, with history = union of both histories plus one new local stamp. The `.conflict-*` file is removed, along with photos referenced only by the losing version. Because the new history contains both sides' latest stamps, it fast-forwards on every phone that imports it, so the conflict can't come back.
  - When an incoming version is applied to a record that has an open conflict on this phone, the app re-checks the `.conflict-*` file: if the incoming history also contains that file's latest stamp (the conflict was already resolved elsewhere), the conflict file and its losing-only photos are removed and the conflict closes; otherwise the conflict stays open.
  - **Wall-clock timestamps** are display-only.
  - **Deletion:** deleting sets `deletedAt` and appends an edit stamp, which makes it a tombstone. The record's photos are removed locally, and the tombstone travels in bundles and merges by the same rules. A deleted record can't reappear from an older bundle. Tombstones are never purged in v1.
- **Survey rounds and section trend:**
  - **Rounds:** each inspection belongs to a survey round for its section.
    - **Identity:** a round is `{roundId (UUID), sectionKey, label, startDate, closedAt?}`. Its identity is `roundId` only, never the label. The round record is stored once, canonically, in `<data folder>/rounds/<roundId>.json`, with its own edit history and the same sync and tombstone rules as inspections. Each inspection.json stores only the `roundId`. Closing or renaming a round edits that one file, and bundles include the round files of every included inspection.
    - **Defaults:** the Inspect screen preselects the section's open round. It creates a new one (label like "Putaran Okt 2026", startDate today) when none is open, when the last inspection is more than 14 days old, or when the round is more than 30 days old. The user can pick another round or close it ("Tutup putaran").
    - **Merging across phones:** rounds created on different phones stay separate, since they have different roundIds. After an import, if two rounds of the same section have start dates within 14 days, History suggests "Gabungkan putaran?". Merging reassigns one round's inspections to the other's roundId as a normal edit with a new stamp, so it propagates through bundles like any other edit. The user can also move a single inspection to another round.
  - **Trend point:** one per round. It's the mean URCI of the latest non-deleted inspection of each sample unit in that round.
  - **Coverage:** the point shows "n dari N unit", where N is the number of distinct units ever inspected in the section. Below 50% coverage, the point is drawn hollow and labeled incomplete.
  - **Outlier flag** (§4-2b): a unit more than 10 points below its round's mean.
- **URCI calculation rules (`urci-engine.js`):**
  - **Density** = quantity / sample area × 100, using the metric curves (premise 3). Density beyond a curve's x-range is clamped to the curve's end and the entry is flagged "di luar grafik / off chart".
  - **q** = the number of deduct values **greater than 5.0** (TM 5-626 §3-4b(3): "the number of individual deduct values greater than 5.0"). Engine test: a deduct of exactly 5.0 is not counted.
  - **q = 0 or 1** uses the q = 1 line (URCI = 100 − TDV, Fig C-8 "q = 0 or 1"). **q > 7** uses the q = 7 curve and is flagged. Tests cover q = 0, q = 1 and q = 9.
  - **TDV range:** TDV beyond 200 is clamped (URCI floor 0) and flagged. For q ≥ 2, a TDV below the curve's first plotted point uses that first point and is flagged.
  - **Rounding:** URCI is stored with 1 decimal and displayed and rated as an integer (round half up), so 84.5 becomes 85, which is Sangat Baik.
  - **Band validation:** bands are integer ranges on the rounded value. The editor takes 4 editable lower limits, which must be strictly decreasing integers between 1 and 99. The bottom band always starts at 0 and the top band always ends at 100. Upper limits are derived (next band's lower limit − 1), so there are never gaps or overlaps. Save is disabled until this is valid.
- **Photo rules:**
  - **Camera capture:**
    - GPS starts watching when the Inspect screen opens, which warms it up.
    - Raw photos waiting for their stamp live in app-private `Directory.Data/pending/` (the app's files directory, which Android never clears on its own), not in the cache. Each is deleted only after its stamped JPEG has been written.
    - At capture, the raw camera image is written immediately to app-private `Directory.Data/pending/<photoUuid>.jpg`, along with a pending entry (capture time and IDs) in app-private storage, and the user keeps working.
    - The app uses the last fix if it is at most 60 s old; otherwise it waits up to 10 s in the background.
    - Then `stamp.js` burns in the stamp (with the fix, or "GPS: n/a"), resizes and compresses it. It writes the final JPEG **once** with create-new into the inspection folder, and deletes the raw temp file. A stamped photo is never redrawn or overwritten.
    - **Recovery:** if the app is killed while photos are pending, the next launch stamps them with their recorded capture time and "GPS: n/a" before anything else.
  - **Gallery import:**
    - The time comes from EXIF DateTimeOriginal. If that's missing (screenshots, photos forwarded through WhatsApp), the user must enter the time manually.
    - GPS comes from EXIF GPS only, never the current position. On Android 10+, location EXIF is redacted for apps without ACCESS_MEDIA_LOCATION, and the Android 13+ photo picker strips it, so v1 does not request that permission. **Gallery imports are expected to show "GPS: n/a"**, and the "IMPOR GALERI" marker makes that clear.
    - The stamp's first line reads "IMPOR GALERI" (EN "GALLERY IMPORT"), plus "WAKTU MANUAL" when the time was typed in.
- **In-app manual and help (added by owner request):**
  - **📖 Panduan / Manual:** bundled offline content in `www/manual/` (HTML), ID and EN versions. It opens from a 📖 icon in the top bar and from Settings. Every section cites its TM 5-626 source paragraph. Contents:
    1. Network setup: branch, section, sample unit of about 230 m² ±90, marking units with a stake (ch. 2, §3-3b).
    2. How to measure each distress 81–87: unit, how to measure, and L/M/H criteria, written from Appendix B with depth and width thresholds (e.g. corrugation 2.5–7.5 cm = M). Illustrations are newly drawn or crew photos, not scans from the PDF.
    3. How URCI is calculated (§3-4): density, deduct, TDV, q (> 5.0), the URCI curve, with the FS 101 metric example worked step by step.
    4. Using the app: inspection, photos, survey rounds, export/import and backups, re-selecting the folder after a reinstall, resolving conflicts.
    5. Reading results: rating bands (site settings vs TM's 7 categories), the outlier flag (§4-2b), and the maintenance priority guide (Fig 4-2, traffic categories I–IV).
  - **(i) popups:** an (i) beside the header of each distress row and key fields (sample area, severity, survey round). It shows a 2–3 line hint in the current language plus a "Panduan §x →" link that opens the matching manual section. Popups are built from the same content files, so they never disagree with the manual.
  - **Source footnote** on every manual page, the same as in Settings.
- **Screens** (wireframe approved; the 📖 icon and (i) popups were added afterwards at the owner's request):
  1. Inspect: DA 7348-R header fields, the block-8 quantity grid with a 📷 button per distress, and live TDV/q/URCI/rating.
  2. Photo: stamped preview, retake or pick from gallery, optional note.
  3. History: section trend chart against the band lines, outlier flag, backup-age warning, graph and xlsx export, import.
  4. Settings: ID/EN, the 5-band editor with reset to default, the data folder path, and the source footnote.
- **Wireframe:** [`docs/designs/urci-field-wireframe.png`](urci-field-wireframe.png)

## Success Criteria
- **Math:** the engine reproduces FS 144 (URCI 25) and FS 101 (URCI 59) within ±2, and every per-curve checkpoint passes. This runs as an automated test in CI.
- **Offline acceptance test:** on a real Android phone in airplane mode, do a full inspection with at least 6 stamped photos. Then calculate URCI, export the PDF and xlsx, view the trend graph, export a bundle, and import it on a second phone. Every step must succeed with zero network.
- **Data survival:** on Android 11, 13 and 14, uninstalling and reinstalling the app leaves the data folder intact. After the user re-selects the folder on first run, all inspections and photos reappear.
- **Sync:**
  - An edit made on phone A only, then imported on B, fast-forwards.
  - An edit made on both phones raises a conflict prompt.
  - A delete on A, then importing B's older bundle into A, does not resurrect the record.
  - All three run as engine-level tests.
- **Speed:** a trained inspector completes one sample unit (entry plus 3 photos) in under 5 minutes.
- **Adoption:** one named mine engineer uses the trend graph to decide one maintenance action within 30 days of release.

### R3-1 — consistency (blocking)

**Problem**

> Import now rejects the whole bundle unless every inspection folder matches `^\d{8}_[A-Za-z0-9-]{1,20}_[A-Za-z0-9-]{1,20}_SU\d{1,4}_[0-9a-f]{8}$`. But folder names are built from user-entered header fields (`{yyyyMMdd}_{branch}_{section}_SU{n}_...`), and the design never says branch and section are restricted or sanitized to 1–20 characters of [A-Za-z0-9-]. A branch typed as 'HR 01', 'Jalan_Utama', a name over 20 characters, or one with Indonesian punctuation gives a folder that the same app created locally but that every other phone rejects on import. The whole bundle then fails, including a Full backup restore.

**Remedy**

> Define one sanitization rule for folder-name components at creation (for example, map anything outside [A-Za-z0-9-] to '-' and truncate to 20 characters), and make the import regex exactly match what the creator can produce. Add a test that exports a record with spaces, underscores and a long section name and imports it on a second phone.

### R3-2 — consistency (blocking)

**Problem**

> Export says 'there's no size cap, because zipping streams natively', and a Full backup holds everything. Import now rejects any bundle over 2 GB uncompressed. Inputs: photos are about 400–600 KB each (premise 7); 2 GB / 0.5 MB ≈ 4,000 photos; at the 6 photos per inspection used in the offline acceptance test, that is ≈ 680 inspections, which is about the 500+ folders Open Question 1 already anticipates. A year of site data therefore produces a Full backup the app itself refuses to import, which breaks the backup/restore and new-phone path.

**Remedy**

> Make export and import agree: either split Full backups into numbered bundles that each stay under the import limits (with import accepting the set), or raise or remove the total limit for bundles while keeping the per-entry and entry-count limits. Add a test that a Full backup over the limit can be restored.

### R3-3 — completeness (blocking)

**Problem**

> Resolution is defined only on the phone that resolves. If phone B also has an open conflict for the same record when A's resolved version arrives, the design does not say whether the fast-forward removes B's `.conflict-*` file and its losing-only photos. A stale conflict left on B would still show '⚠ Konflik', and resolving it from the stale side-by-side view would revert A's decision. If A and B both resolve independently, neither new history contains the other's new stamp, so a conflict does come back, which contradicts 'the conflict can't come back'.

**Remedy**

> Specify that applying any incoming version whose history contains the conflict copy's latest stamp (or supersedes both sides) clears the local `.conflict-*` file and photos referenced only by the losing versions. Replace 'can't come back' with the true guarantee: it does not recur after one-sided resolution, and two independent resolutions raise one new conflict.

### R3-4 — completeness (blocking)

**Problem**

> The round record (label, startDate, closedAt) is copied into every inspection of the round, but no rule keeps the copies consistent. Closing a round ('Tutup putaran') or renaming it changes which copy? If only inspections saved later carry closedAt, different inspections of the same roundId disagree on whether the round is closed and on its label, and phones that receive only some of those inspections disagree on the open-round default and on the trend point's label. **Remedy**

### R3-5 — feasibility (blocking)

**Problem**

**Remedy**

### R3-6 — feasibility (blocking)

## CEO Review Amendments (approved 2026-11-01, /plan-ceo-review, HOLD SCOPE)
These amendments are approved and **supersede** any earlier text in this doc that conflicts with them.

- **SYNC-1 (D15, replaces the D4 deferral):**
  - **Conflicts:** a conflict is closed with a one-tap "Pakai versi saya / Pakai versi masuk" (keep mine / take incoming), after a short list of the fields that differ. Resolution writes history = union of both histories plus a new local stamp.
  - **Rounds:** `roundId` is deterministic, `<sectionKey>-<yyyy-MM>`. Phones agree on rounds automatically, so there's no merge step. The 14-day / 30-day auto-round rules and the "Gabungkan putaran" suggestion are removed. `rounds/<roundId>.json` still holds the label and closedAt under the sync rules. A survey crossing a month boundary lands in two rounds (accepted tradeoff).
- **ERR-1 (D5): crash-safe saves on SAF.** SAF has no atomic replace (outside-voice correction), so the safe-replace protocol is:
  1. write `inspection.json.new`;
  2. rename the current file to `inspection.json.old`;
  3. rename `.new` to `inspection.json`;
  4. delete `.old`.

  On startup, any folder holding `.new` or `.old` is recovered: if `.json` is valid, delete leftovers; else promote `.new` (if valid), else `.old`.
  - Before every photo, export and import, free space is checked against the expected size × 1.5. If it's short, an ID/EN message says how much space is needed, and nothing partial is written.
  - Photo writes check that the name exists first, since SAF auto-renames on a clash instead of failing. On a clash, a new UUID suffix is generated.
- **ENG-1 (D6): engine boundary rules.**
  - URCI is clamped to 0–100 on every curve, including q = 1.
  - A density below a curve's first plotted point is interpolated linearly from (0, 0).
  - The display integer is rounded once from the raw value (round half up).
  - The section mean and the outlier test use raw values.
- **IMP-1 (D7): import and stamp failures.**
  - Unsafe paths, size limits, a bad or unsupported manifest version, or a manifest `count` that doesn't match the number of inspection.json entries reject the **whole** bundle, with a specific ID/EN message for each class.
  - Schema-invalid records are skipped, and the result reads "X diimpor, Y dilewati (alasan)".
  - If stamping runs out of memory, it retries at 1280 px. If that still fails, the raw photo stays pending with "⚠ Foto belum diproses".
- **SEC-1 (D8): injection defense.**
  - Record text is rendered via `textContent` only, never `innerHTML`.
  - Strict CSP: `default-src 'self'; img-src 'self' data: blob:; script-src 'self'; style-src 'self'`.
  - The schema caps text lengths: branch/section 40, inspector 60, remarks 1000, note 300.
  - An evil-bundle test fixture covers this.
- **UX-1 (D9): entry protection.**
  - The draft autosaves to app-private storage on every change, and reopening asks "Lanjutkan draf?".
  - Back with unsaved changes asks for confirmation.
  - Save is disabled while a save is in flight.
- **SYNC-2 (D10): photo consistency.**
  - After applying any incoming version or tombstone, photo files that the record no longer lists are deleted.
  - Section/date share selections include matching tombstones.
  - The stamp step checks that the entry is still live before writing, and drops the raw photo otherwise.
- **OBS-1 (D11): diagnostics.** A 1 MB rolling log lives in app-private storage, with no photos or GPS. It records saves, imports (X/Y with reasons), exports, stamp retries and errors, plus app and Android versions. Settings gets "Ekspor diagnostik".
- **DEP-1 (D12): release safety.**
  - CI publishes a SHA-256 checksum with each release, and fails if `versionCode` didn't increase.
  - A hidden Settings "Uji mandiri" runs FS 101 and FS 144 on the device and shows pass/fail. It's the post-install smoke check.
- **UI-1 (D13): field-ready UI.**
  - Tap targets are at least 48×48 dp, larger in the quantity grid.
  - High-contrast theme, body text at least 16 sp, numeric keypads for quantities.
  - A one-time outdoor test with gloves on a real phone.

## Design Review Amendments (approved 2026-11-02, /plan-design-review)
These amendments are approved and supersede conflicting screen descriptions above (including the wireframe where they differ).

**Information architecture**
- **IA-1 (D4):** Riwayat opens on a **Sections list** sorted worst-first. Each row shows section name, latest URCI, rating chip (text + color), change since last round (e.g. "−12 ▼") and coverage "n dari N unit". Tapping a row opens the section trend.
- **IA-2 (D5):** Inspect has a **sticky result bar** (~72 dp, always above the keyboard) showing URCI · rating · TDV · q. After the first fill, the header collapses to one summary line, "I-HR01 / S03 / SU2 · 167 m² · Putaran Nov 2026 ✎", that expands on tap.
- **IA-3 (D6):** the section trend screen order is:
  1. headline "Sekarang 36 · Buruk (dari 78, −42)";
  2. the chart;
  3. flags (outlier, conflict, incomplete);
  4. the rounds table;
  5. actions (graph export).

  The backup reminder is a slim banner on File and Settings, shown only when the last backup is more than 7 days old.
- **IA-4 (D7):** the **File** tab is the data hub: Backup penuh, Impor bundel, Bagikan pilihan, the list of past exports with Open/Share, and Ekspor diagnostik. History keeps only graph export; Inspect keeps only "PDF inspeksi ini".

**States**
- **ST-1 (D8): first run.**
  - A welcome screen shows the app name, "Data inspeksi disimpan di folder HP Anda", and the button "Pilih folder data" (Documents/URCI suggested).
  - Outcomes: existing data → "Ditemukan N inspeksi · Lanjutkan"; empty folder → "Folder baru siap"; cancel → reason + "Coba lagi".
  - Then a skippable, one-time 3-step tip (Isi → Foto → Simpan).
- **ST-2 (D9): where messages appear.**
  - Field problems: red text under the field.
  - Finished action: a 3 s toast at the bottom.
  - Blocking or data-losing problems: a dialog with one clear button.
  - Standing conditions (old backup, open conflicts): a slim banner.
  - Per-item warnings (Foto diubah, File rusak, Foto belum diproses, di luar grafik): an icon chip on that row or cell.
  - Every empty state gets one line of explanation plus one action, e.g. Riwayat → "Belum ada inspeksi" + "Mulai inspeksi"; a single round → one point plus "Butuh 2 putaran untuk tren"; File with no exports → "Belum ada ekspor".
- **ST-3 (D10): conflict and import screens.**
  - **Conflict:** the "Konflik (n)" banner opens a list. Each item shows only the differing fields in two columns, Versi saya | Versi masuk, and two equal-size buttons, "Pakai versi saya" / "Pakai versi masuk", with no default selected.
  - **Import result:** a full-screen summary, "✔ X diimpor · ⚠ Y dilewati", listing each skipped item with its reason, a "Lihat detail di diagnostik" link, and "Selesai".
- **ST-4 (D11): photo processing.** After capture, the app returns to the grid immediately. The camera control on that cell shows processing ⏳ → count → ⚠ (failed). Opening it shows "Memproses… mencari GPS (n s)" over the raw image until the stamp is ready. (Icons per SLOP-1.)

**User journey**
- **UJ-1 (D12): declined.** There is a single Save, which returns to an empty form.
- **UJ-2 (D13): branch and section pickers.** Both fields pick from earlier values (most recent first), with "+ Baru" to add one. New names are trimmed and uppercased, and a near-duplicate prompts "Maksud Anda I-HR01?". The list is stored in settings.json.
- **UJ-3 (D14): calculation panel.** Tapping the result bar opens a block-9 table. Each entered distress row shows code + short name, severity, quantity + unit, density %, deduct, TM figure (e.g. "Gbr. C-3") and the "di luar grafik" flag. Below that: TDV, q ("dihitung jika > 5,0"), URCI, rating, and the band table used. The PDF prints the same table.

**AI slop**
- **SLOP-1 (D15): icons.** Emoji are replaced by a bundled Material Symbols subset (~20 icons, offline): monochrome, 24 dp inside 48 dp targets, colored only for status (warning amber, error red), each with a TalkBack label.

**Design system**
- **DS-1 (D16): resolved 2026-11-02** by `/design-consultation`, which wrote `DESIGN.md` ("Certified field form": navy ink #1D3B6E on white, Barlow / Barlow Semi Condensed / IBM Plex Mono bundled, 8 dp grid, 72 dp cells with corner photo badge, band colors + labels). All screens follow DESIGN.md.

**Responsive and accessibility**
- **RA-1 (D17): grid layout.** Rows show code + short name (81 Penampang, 82 Drainase, 83 Keriting, 84 Debu, 85 Lubang, 86 Alur, 87 Agregat); the full name is in the (i) popup. L/M/H cells are 72 dp, and **the camera control sits on each filled cell**, so a photo always belongs to one exact severity. Full names show on wide or landscape screens. Tested at the largest system font, where labels wrap to 2 lines and are never truncated.
- **RA-2 (D18): accessibility.**
  - Every cell has a full TalkBack label, e.g. "Keriting, sedang, 83,7 meter persegi".
  - The URCI is a polite live region.
  - All icons have labels, and status is always shown as text, never by color alone.
  - Focus order runs header → grid row by row → Save.
  - One TalkBack pass per screen.
